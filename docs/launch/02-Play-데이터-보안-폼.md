# Google Play — 데이터 보안(Data safety) 폼 답안

> **상태: 초안.** Play Console → 앱 콘텐츠 → 데이터 보안 에 그대로 옮겨 적는다.
> 답안은 **저장소의 실제 코드**에서 뽑았다. 근거 파일을 각 항목에 적어 둔다.
>
> ⚠️ **틀리게 적으면 반려되고, 나중에 드러나면 앱이 내려간다.** 기능을 바꾸면 이 문서도 바꾼다.
> 특히 수익화(광고·결제)를 붙이는 순간 **여러 답이 뒤집힌다.**

---

## 0. 먼저 답하는 큰 질문 세 개

| 질문 | 답 | 근거 |
|---|---|---|
| 데이터를 수집하는가 | **예** | 러닝 기록을 클라우드에 백업한다 |
| 데이터를 제3자와 공유하는가 | **아니요** | 판매·제공 경로 없음. 이용자가 직접 내보내는 것은 '공유'가 아니다 |
| 전송 중 암호화되는가 | **예** | 전 구간 HTTPS/TLS(Firebase SDK) |
| 삭제를 요청할 수 있는가 | **예** | 앱 내 계정 삭제로 전량 삭제 |

---

## 1. 위치 (Location)

### 대략적인 위치 (Approximate location)
- 수집: **예**
- 공유: 아니요
- **필수/선택**: 선택 (앱 사용에 필수 아님 — 실내 러닝은 위치 없이 기록된다)
- 목적: **앱 기능** (App functionality)
- 이유: 러닝 거리·경로 측정

### 정확한 위치 (Precise location)
- 수집: **예**
- 공유: 아니요
- **필수/선택**: 선택
- 목적: **앱 기능**
- 이유: 러닝 거리·경로·페이스 측정, 러닝화 누적 거리 산출

> **주의**: 광고·마케팅 목적 체크 금지. 위치로 광고하지 않는다.
> `ACCESS_BACKGROUND_LOCATION` 은 **선언하지 않는다** — 러닝 중 포그라운드 서비스로만 동작한다
> (`android/app/src/main/AndroidManifest.xml` 주석 · 회귀 가드 `__tests__/nativePermissions.test.ts`).

## 2. 개인 정보 (Personal info)

### 이름 (Name)
- 수집: **예** — 소셜 로그인이 주는 표시 이름 / 이용자가 정한 닉네임
- 공유: 아니요
- 필수/선택: 선택 (닉네임은 바꾸거나 비울 수 있다)
- 목적: **앱 기능**, **계정 관리**
- 근거: 프로필 문서의 `nickname`

### 이메일 주소 (Email address)
- 수집: **예** — 소셜 로그인 제공자(구글·애플·카카오·네이버)가 전달
- 공유: 아니요
- 필수/선택: **필수** (계정 식별에 쓰인다)
- 목적: **계정 관리**
- 근거: Firebase Authentication

### 사용자 ID (User IDs)
- 수집: **예** — Firebase UID
- 공유: 아니요
- 필수/선택: 필수
- 목적: **앱 기능**, **계정 관리**

## 3. 사진 및 동영상 (Photos and videos)

### 사진 (Photos)
- 수집: **예** — 이용자가 직접 올린 러닝화·메달·기록증 사진
- 공유: 아니요
- 필수/선택: **선택**
- 목적: **앱 기능**
- 저장: 이용자 본인 계정 폴더(`users/<uid>/…`), 본인만 접근

---

## 4. 건강 및 피트니스 (Health and fitness)

### 건강 정보 (Health info)
- 수집: **예** — 심박수(연동 시), 체중(이용자 입력, 칼로리 계산용)
- 공유: 아니요
- 필수/선택: **선택**
- 목적: **앱 기능**
- 출처: Health Connect(Android) / HealthKit(iOS). **우리가 센서로 재지 않는다** — 워치가 기록한 것을 읽는다.

### 피트니스 정보 (Fitness info)
- 수집: **예** — 러닝 거리·시간·페이스·케이던스·고도·칼로리
- 공유: 아니요
- 필수/선택: **선택**
- 목적: **앱 기능**

> **Health Connect 는 Play 의 별도 심사 대상이다.** 데이터 보안 폼과 함께
> '건강 데이터 접근 선언'을 제출해야 하며, 심사 기간은 콘솔에서 확인한다.
> 선언한 권한: `READ_HEART_RATE` · `READ_RESTING_HEART_RATE` · `READ_EXERCISE` ·
> `WRITE_EXERCISE` · `WRITE_DISTANCE` · `WRITE_TOTAL_CALORIES_BURNED`

---

## 5. 앱 활동 (App activity)

### 앱 상호작용 (App interactions)
- 수집: **예**
- 공유: 아니요
- 필수/선택: 선택
- 목적: **분석 (Analytics)**
- 내용: 러닝 시작/저장/취소, 로그인, 온보딩 단계, 신발 등록, 권한 수락 여부

> **거리·시간은 원값이 아니라 버킷으로만 보낸다** — `km_bucket`, `minute_bucket`
> (`lib/productAnalytics.ts`). 개인을 특정할 수 있는 수치를 애널리틱스로 보내지 않는다.

### 앱 내 검색 기록 (In-app search history)
- 수집: **예** — 카탈로그에 없는 러닝화를 찾았을 때 그 검색어
- 공유: 아니요
- 필수/선택: 선택
- 목적: **앱 기능** (카탈로그 보완)
- 내용: 브랜드 + 모델 문자열만. **계정 정보를 함께 보내지 않는다**
  (`ShoePicker.tsx` — "신호의 목적은 '무엇이 없었나'이지 '누가 찾았나'가 아니다")

## 7. 기기 또는 기타 ID (Device or other IDs)

- 수집: **예** — 푸시 토큰(FCM), Firebase 설치 ID
- 공유: 아니요
- 필수/선택: 선택
- 목적: **앱 기능**(푸시 알림), **분석**

> **광고 ID 는 수집하지 않는다.** Firebase Analytics 가 자동 병합하는 권한 셋을
> 매니페스트에서 명시적으로 제거해 뒀다(`tools:node="remove"`):
> `com.google.android.gms.permission.AD_ID` · `ACCESS_ADSERVICES_AD_ID` ·
> `ACCESS_ADSERVICES_ATTRIBUTION`.
> 광고 SDK 도 없다(`package.json` 에 admob·ads 계열 의존성 없음).
> 따라서 데이터 보안 폼에서 **광고 ID 항목을 체크하지 않는다.**

## 8. 보안 관행 (Security practices)

| 항목 | 답 |
|---|---|
| 전송 중 암호화 | **예** — 전 구간 HTTPS/TLS |
| 삭제 요청 가능 | **예** — 앱 내 계정 삭제로 전량 삭제 |
| 독립적 보안 검토 | 아니요 |
| 가족 정책 준수 | 해당 없음(어린이 대상 앱 아님) |

---

## 9. 접수 전 결정할 것

1. ~~광고 ID 수집~~ — **이미 제거돼 있다**(위 §7). 결정할 것 없음.
2. **Health Connect 심사 기간** — 콘솔에서 확인해 출시 일정에 반영한다.
3. **애널리틱스 자체를 출시 시점에 켤까** — 지금 켜져 있다. 끄면 §5·§7 이 대부분 사라지지만
   출시 후 지표를 못 본다. 켜 두는 것을 권한다(버킷만 보내므로 위험이 낮다).

## 10. 이 문서를 고쳐야 하는 변경

- 광고·인앱결제 도입 → §1·§7 뒤집힘, '공유' 질문 재검토
- 제3자 SDK 추가 → 그 SDK 가 무엇을 보내는지 확인 후 반영
- 실시간 위치 공유(라이브 비콘) 기능 도입 → §1 '공유' 답이 **예**로 바뀐다
- `ACCESS_BACKGROUND_LOCATION` 부활 → 별도 선언 양식 + **시연 영상** 제출이 다시 붙는다
