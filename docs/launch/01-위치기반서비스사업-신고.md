## 2. 사업계획서 — 사업자 현황 및 사업 내용

### 2.1 서비스 개요

**서비스명**: Keego (키고)
**형태**: 모바일 애플리케이션 (iOS · Android)
**분류**: 러닝 기록 및 러닝화 관리 서비스
**과금**: 현재 없음(무료). 향후 유료 기능 도입 시 별도 검토.

러너가 달린 거리·경로·시간을 기록하고, 그 거리를 **신고 있는 러닝화에 자동으로 누적**해
교체 시점을 알려 주는 앱이다. 러닝화의 수명 관리가 다른 러닝 앱과의 차이점이다.

### 2.2 위치정보를 무엇에 쓰는가

| 용도 | 설명 |
|---|---|
| 러닝 거리 측정 | 이동 궤적으로 거리를 계산해 기록에 저장 |
| 경로 지도 | 달린 경로를 지도로 표시(사용자 본인만) |
| 페이스 산출 | 거리와 시간으로 km당 속도 계산 |
| 고도 변화 | 오르내림을 반영한 보정 페이스 산출 |
| 러닝화 마모 누적 | 측정된 거리를 선택한 러닝화의 누적 거리에 더함 |

**위치정보를 이용한 광고·마케팅·프로파일링은 하지 않는다.**
**실시간 위치 공유·추적 기능은 없다.**

### 2.3 수집 방식과 시점

- **수집 주체**: 이용자 단말의 GPS(단말 OS 제공). 별도의 위치정보사업자로부터 제공받지 않는다.
- **수집 시점**: 이용자가 **직접 '러닝 시작'을 누른 동안에만** 수집한다. 앱을 켜 두기만 해서는 수집하지 않는다.
- **종료**: 이용자가 러닝을 종료·저장·취소하면 즉시 수집을 멈춘다.
- **화면이 꺼진 동안**: 러닝 중에는 **알림이 표시되는 포그라운드 서비스**로 동작한다.
  이용자가 기록 중임을 항상 알 수 있다.
  ※ Android 의 `ACCESS_BACKGROUND_LOCATION`(항상 허용) 권한은 **선언하지 않는다.**
     이용자가 시작한 포그라운드 서비스만으로 동작하므로 필요가 없다.

### 2.4 개인위치정보의 제3자 제공

**없다.** 수집한 위치정보를 제3자에게 제공하거나 판매하지 않는다.

- 이용자가 **직접** '내보내기(GPX)'를 눌러 자신의 기기에 파일로 저장하는 경우만 예외이며,
  이는 이용자 본인의 조작에 의한 것이다.
- 이용자가 **직접** 러닝 기록을 공유(이미지 카드)할 수 있으나, 여기에는 지도 이미지가
  포함될 수 있음을 사전 고지하고 이용자가 선택한다.

### 2.5 위치정보 처리 위탁

| 수탁자 | 위탁 내용 | 위치 |
|---|---|---|
| Google LLC (Firebase / Cloud Firestore) | 이용자 데이터 저장·백업 | asia-northeast3 (서울) |

## 3. 사업용 주요 설비의 내용 및 설치 장소

자체 서버를 운용하지 않는다. 클라우드 관리형 서비스만 사용한다.

| 설비 | 사업자 | 리전 | 용도 |
|---|---|---|---|
| Cloud Firestore | Google Cloud | **asia-northeast3 (서울)** | 러닝·러닝화 기록 저장 |
| Cloud Functions | Google Cloud | **asia-northeast3 (서울)** | 소셜 로그인 토큰 발급 등 |
| Firebase Authentication | Google | — | 계정 인증 |
| Cloud Storage | Google Cloud | **asia-northeast3 (서울)** | 이용자가 올린 사진 |

**개인위치정보를 포함한 데이터는 국내(서울) 리전에 저장된다.**

## 4. 위치정보 보호조치 (위치정보법 제16조)

> 아래는 저장소의 실제 구현이다. 각 항목의 근거 파일을 함께 적는다.

### 4.1 접근 통제

- 모든 데이터는 **이용자 본인만** 읽고 쓸 수 있다. 서버 보안 규칙이 이를 강제한다.
  ```
  match /userBackups/{uid} {
    allow read, write: if signedIn() && request.auth.uid == uid;
  }
  ```
  (`firestore.rules` — 하위 컬렉션까지 같은 규칙을 명시적으로 반복 적용)
- **관리자 열람 경로가 없다.** 별도의 백오피스·운영자 조회 화면을 만들지 않았다.
- 인증되지 않은 요청은 전부 거부된다.

### 4.2 전송 구간 보호

- 단말 ↔ 서버 통신은 **전 구간 HTTPS/TLS**(Firebase SDK 기본).
- 평문 HTTP 통신 경로가 없다.

### 4.3 저장 시 보호

- 클라우드 제공자의 **저장 시 암호화**(encryption at rest) 적용.
- 단말 내부 저장은 앱 전용 영역(sandbox)에 두며, 다른 앱이 읽을 수 없다.
- Android 릴리스 빌드는 `allowBackup="false"` 로 **기기 백업을 통한 유출 경로를 차단**한다.

### 4.4 수집 최소화

- 러닝 중이 아닐 때는 위치를 수집하지 않는다.
- 저장 시 경로를 **단순화**해 원본보다 적은 점만 남긴다(정확도 손실 없는 범위).
- 위치정보에 이용자 실명·연락처를 결합해 저장하지 않는다.

### 4.5 이용자 통제권

| 권리 | 구현 |
|---|---|
| 동의 | 최초 위치 권한 요청 시 OS 다이얼로그 + 앱 내 사전 안내 |
| 열람 | 기록 탭에서 본인의 모든 러닝·경로 확인 |
| 정정 | 기록 수정(거리·시간·신발) 가능 |
| 삭제 | 러닝 개별 삭제 · **계정 삭제 시 전량 삭제** |
| 이동 | GPX 내보내기(표준 포맷) |
| 철회 | OS 설정에서 위치 권한 해제 시 즉시 수집 중단 |

### 4.6 파기

- 이용자가 러닝을 삭제하면 **본문·경로·시계열 사이드카까지 함께 삭제**한다.
- 계정 삭제 시 러닝·러닝화·사진·프로필을 전량 삭제한다.
- 보존 기간을 따로 두지 않는다 — 이용자가 지우면 지워진다.

### 4.7 접근기록 보관 (법 제16조제2항)

> **⚠️ 확인 필요.** 위치정보법은 개인위치정보 취급 사실에 대한 **접근기록을 6개월 이상
> 보관**하도록 정한다. 현재 우리 구조는 서버 코드 없이 단말이 Firestore 에 직접
> 접근하므로, 그 기록을 우리가 남기지 않는다(클라우드 제공자 로그는 존재).
>
> 이 항목은 **신고 전에 센터에 확인해야 한다.** 필요하다면 Firestore 접근 로그를
> 6개월 보관 설정으로 남기는 것으로 대응할 수 있다.
