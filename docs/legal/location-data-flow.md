# 위치정보 수집·저장·삭제 구조 설명자료

> **용도:** 위치기반서비스사업 신고 제출서류 중 「서버 및 시스템 구조 설명자료」 및
> 실무상 요구되는 "위치정보가 어떻게 수집·저장·삭제되는지" 정리본.
> **작성 2026-07-31 · 기준 커밋 `6bee2e1` · 근거는 전부 실제 코드(파일:줄번호 표기).**
>
> ⚠️ 이 문서는 **기술 구조를 사실대로 기술한 것**이며 법적 판단(신고 대상 여부·의무 범위)을
> 담지 않는다. 법적 판단은 방통위 확인 또는 법률 자문으로 확정할 것.

## 1. 수집

### 1.1 언제 수집하나 — **러닝 중에만**

| 시점 | 동작 | 근거 |
|---|---|---|
| 앱 실행·평상시 | **수집 안 함** | 위치 구독 자체가 러닝 시작 시에만 열린다 |
| 러닝 시작 | 위치 구독 시작 | `lib/locationService.ts:145` `startTracking()` |
| 러닝 종료/중단 | 구독 해제 | `lib/locationService.ts:185` `stopTracking()` |

권한은 **첫 러닝 시작 직전**에 요청하며, 그 전에 목적을 안내하는 화면을 한 번 보여준다
(`LocationPrimeScreen.rn.tsx`). 권한 요청 자체는 `lib/locationService.ts:84-101`.

### 1.2 무엇을 수집하나

OS 위치 서비스가 주는 값 중 아래만 사용한다 (`lib/locationService.ts:46-59`).

| 항목 | 줄 | 용도 |
|---|---|---|
| 위도 `latitude` | :49 | 이동 거리·경로 |
| 경도 `longitude` | :50 | 〃 |
| 정확도 `accuracy` | :51 | **품질 필터링용** — 부정확한 신호를 거리에서 배제 |
| 고도 `altitude` | :52 | 누적 상승고도·경사 보정 |
| 속도 `speed` | :55 | 현재 페이스 표시 보조 |
| 시각 `timestamp` | :57 | 구간 시간·중복 제거 |

**수집하지 않는 것:** 통신사 정보, 기지국·Wi-Fi 스캔 목록, 주소록, 광고 식별자.

### 1.3 수집 주기·정밀도

- **1초 간격**(`timeInterval: 1000`), 거리 기반 필터 없음(`distanceInterval: 0`) — `lib/locationService.ts:32-34`
- 정확도 등급 `BestForNavigation` (내비게이션급)
- 화면이 꺼져도 기록이 끊기지 않도록 **포그라운드 서비스** 방식으로 동작
  (`lib/locationService.ts:165-176`). Android 는 진행 중 알림이 표시된다.

### 1.4 수집 즉시 하는 처리(기기 내)

원본 좌표를 그대로 쓰지 않는다. 기기 안에서 다음을 거친다.

| 처리 | 목적 | 근거 |
|---|---|---|
| 정확도 게이트(20m 초과 배제) | 부정확 신호로 인한 거리 과대 방지 | `lib/engineConstants.ts:7` |
| 워밍업 3개 fix 제외 | 시작 직후 콜드픽스 배제 | `lib/engineConstants.ts:10` |
| 속도·거리 상한(12m/s, 300m) | GPS 점프 배제 | `:13`, `:42` |
| 칼만 필터 | 좌표 평활화 | `lib/kalman.ts` |
| **경로 단순화(최대 200점)** | 저장 용량 축소 | `lib/geo.ts:86-91`, `screens/RunEngine.tsx:747` |

즉 **저장되는 경로는 원본 전체가 아니라 러닝 1건당 최대 200개 좌표로 축약된 것**이다.

## 2. 저장

### 2.1 저장 위치 — 두 곳

```
[사용자 기기]                          [클라우드 — Google Firebase Firestore]
AsyncStorage                            userBackups/{uid}
  route_<runId>  ← 경로 원본(로컬 정본)     ├─ runs[].route        (레거시 경로)
                                          └─ runDetails/{runId}
                                               └─ route            (현행 경로 저장 위치)
```

| 구분 | 위치 | 근거 |
|---|---|---|
| 기기 내 | `route_<러닝ID>` 키 | `lib/bootCache.ts:33,37,47` |
| 클라우드 본체 | `userBackups/{uid}` | `lib/firebaseCloudPort.ts:34,180` |
| 클라우드 사이드카 | `userBackups/{uid}/runDetails/{runId}` | `lib/firebaseCloudPort.ts:186` |

> 2026-07-30 구조 변경: 경로를 본문에서 **런별 하위 문서(사이드카)** 로 옮겼다
> (`lib/runDetailSync.ts:34`). 문서 크기 상한 대응이며, 저장 주체·목적·보유기간은 동일하다.

### 2.2 클라우드 전송

- **전송 시점:** 러닝 저장 후, 그리고 신발·기록·설정 변경 시 디바운스 동기 (`App.tsx` `runCloudSync`)
- **전송 방식:** Firebase SDK — **HTTPS/TLS 암호화**. 평문 통신은 앱 전체에서 차단
  (`ios` `NSAllowsArbitraryLoads: false` · Android release `usesCleartextTraffic="false"`)
- **로그인하지 않으면 전송하지 않는다** — 클라우드 동기는 계정이 없으면 건너뛴다
  (`App.tsx` runCloudSync 의 `!authUser?.uid` 가드). 이 경우 위치정보는 **기기에만** 남는다.

### 2.3 저장 주체 및 국외 이전

| 수탁자 | 역할 | 소재 |
|---|---|---|
| Google LLC (Firebase Firestore) | 저장·동기화 | 미국 등 Google Cloud 데이터센터 |
| Google LLC (Google Maps SDK) | **지도 화면 표시** | 지도 타일 요청 시 화면 영역 좌표가 전달됨 |

처리방침 §5(위탁)·§6(국외 이전)에 고지돼 있다(`docs/privacy.html:144-145`).
**역지오코딩(좌표→지역명)은 기기 운영체제 내에서 수행**하며 외부로 좌표를 보내지 않는다
(`lib/geocode.ts`, 처리방침 §5 주석).

### 2.4 접근 통제

- 클라우드의 위치정보는 **본인 계정만** 읽고 쓸 수 있다 — `firestore.rules:55-60`
  (`userBackups/{uid}` 및 그 하위 전체에 `request.auth.uid == uid` 강제)
- 타 사용자·비로그인 접근은 전부 차단. **에뮬레이터에서 공격 35건을 실제로 시도해
  전부 차단됨을 확인**했다(`tests/rules/attack.rules.test.ts`, 재현 `npm run test:rules`)
- 앱 무결성 검증(App Check)으로 정상 앱 이외의 요청을 걸러낸다 — `lib/appCheck.ts`

## 3. 이용

수집한 위치정보로 하는 처리는 다음이 전부다.

| 기능 | 처리 내용 | 근거 |
|---|---|---|
| 거리·페이스 | 좌표 간 거리 누적 | `lib/geo.ts`, `lib/runTracker.ts` |
| 경로 지도 | 저장된 좌표를 화면에 폴리라인으로 표시 | `lib/route.ts`, `CourseMap.tsx` |
| 고도·경사 보정 | 고도 변화로 경사 보정 페이스 산출 | `lib/elevation.ts` |
| 러닝화 마모 | **거리만** 사용(좌표 아님) → 신발 수명 차감 | `lib/shoe.ts` |
| GPX 내보내기 | 사용자가 직접 요청할 때만 파일로 내보냄 | `lib/gpx.ts` |
| 대회 자동 감지 | 러닝 시작 좌표를 **국내 대회 개최지 좌표와 대조** | `lib/raceStore.ts:28-29` |

**하지 않는 것:** 위치 기반 광고·쿠폰, 위치 이력의 프로파일링, 제3자 제공·판매,
실시간 위치 공유(타인에게 현재 위치를 알리는 기능 없음).

## 4. 보유 및 삭제

### 4.1 보유 기간

| 대상 | 기간 |
|---|---|
| 위치정보(경로) | **회원 탈퇴 또는 이용자의 개별 삭제 시까지** |
| 위치정보 이용·제공사실 확인자료 | 위치정보법 제16조에 따라 **6개월**(처리방침 §3) |

### 4.2 이용자가 직접 삭제하는 경로

| 방법 | 결과 |
|---|---|
| **러닝 1건 삭제** (기록 탭) | 그 러닝의 경로가 기기·클라우드 양쪽에서 삭제 대상이 된다(삭제 표식이 기기 간 전파) |
| **앱 삭제** | 기기 내 위치정보 전부 소멸 |
| **회원 탈퇴** (마이 → 계정) | 아래 4.3 |

### 4.3 회원 탈퇴 시 삭제 절차 — 코드 근거

`lib/firebaseCloudPort.ts` `deleteAccount()` 가 **순서대로** 수행한다.

| 순서 | 대상 | 근거 |
|---|---|---|
| 1 | `userBackups/{uid}/runDetails/*` **순회 삭제** — 경로가 저장된 하위 문서 | `:233` |
| 2 | `userBackups/{uid}` 본체 삭제 | `:236` |
| 3 | 월간 랭킹 엔트리 삭제 | `:250` |
| 4 | Firebase 인증 계정 삭제 | `deleteUser` |
| 5 | **기기 내 전체 삭제** (`AsyncStorage.clear()`) — `route_*` 포함 | `App.tsx:1308` |

> 1번을 별도로 도는 이유: Firestore 는 **상위 문서를 지워도 하위 컬렉션이 남는다.**
> 그대로 두면 경로가 고아 데이터로 남으므로 명시적으로 순회 삭제한다.
> 계정 삭제(4번)를 먼저 하면 권한이 사라져 지울 수 없으므로 **데이터를 먼저 지운다.**

### 4.4 현재 남는 것 — 정직한 기재

탈퇴 시 **아래 두 컬렉션은 삭제되지 않는다.** 위치정보는 아니지만 계정 식별자를 포함한다.

| 컬렉션 | 내용 | 상태 |
|---|---|---|
| `search_misses` | 러닝화 검색어 + 계정 식별자 | 삭제 경로 없음 |
| `shoe_requests` | 입력한 브랜드·모델 + 계정 식별자 | 삭제 경로 없음 |

규칙상 클라이언트가 조회·삭제할 수 없어(`firestore.rules:116,124`) 앱이 스스로 지울 수단이
없다. **개선 예정 항목으로 기재한다**(계정 식별자를 애초에 저장하지 않는 방향 검토 중).

## 5. 시스템 구조

### 5.1 전체 구성 — 자체 서버 없음

```
┌──────────────────────────────┐
│  사용자 기기 (iOS / Android)   │
│                              │
│  OS 위치서비스 → 앱(기기 내 처리) │   ← 수집·필터링·계산 전부 기기에서
│         │                    │
│         ├─ 로컬 저장(AsyncStorage)
│         │                    │
│         └─ HTTPS/TLS ────────┼──→ Google Firebase (Firestore)  … 위치정보 저장
│                              │        · Firebase Auth          … 계정 인증
│                              │        · Crashlytics            … 오류 진단(위치 미포함)
│                              │
│         └─ HTTPS ────────────┼──→ Cloud Functions (asia-northeast3, 서울)
└──────────────────────────────┘        · 소셜 로그인 토큰 검증
                                        · 러닝화 가격 조회(위치 미전달)
```

**운영 사업자가 직접 구축·운영하는 서버는 Cloud Functions 1개뿐이며, 그 함수는 위치정보를
받지도 처리하지도 않는다**(`functions/index.js` — 소셜 로그인 토큰 검증 + 쇼핑 가격 조회).
위치정보는 앱에서 Firebase Firestore 로 **직접** 전송된다.

### 5.2 위치정보가 지나가는 경로 요약

| 단계 | 어디서 | 무엇이 |
|---|---|---|
| ① 수집 | 기기 OS | 좌표·정확도·고도·속도·시각 |
| ② 처리 | **기기 내** | 필터링·칼만 평활·거리 계산·200점 축약 |
| ③ 로컬 저장 | 기기 AsyncStorage | 축약된 경로 |
| ④ 전송 | HTTPS/TLS | 로그인 상태에서만 |
| ⑤ 클라우드 저장 | Firestore (Google LLC) | 본인만 접근 가능 |
| ⑥ 삭제 | 탈퇴·기록 삭제·앱 삭제 | §4 |

### 5.3 개발·운영 체계

- 개발: 1인 개발(외주 없음). 저장소 `solelife9/solemate`
- 위치정보 처리 로직은 **순수 함수로 분리**돼 자동 테스트로 검증된다
  (`lib/runTracker.ts`, `lib/geo.ts` 등 — 2,615개 테스트)
- 보안 규칙 회귀는 에뮬레이터 기반 계약·공격 테스트 71건으로 상시 검증
  (`npm run test:rules`)
