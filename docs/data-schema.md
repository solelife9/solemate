# 저장 스키마와 변경 절차

> 2026-07-27 신설(출시 심사 TOP30 #20). 출시 후에는 **사용자 기기에 되돌릴 수 없는 데이터**가
> 쌓인다. 그때부터 스키마 변경은 코드 변경이 아니라 **마이그레이션**이다.
> CLAUDE.md Iron Law: *사용자 데이터(신발·런 기록) 파괴적 변경/마이그레이션 금지.*

## 1. 데이터가 사는 곳

| 계층 | 위치 | 성격 |
|---|---|---|
| 부팅 캐시 | AsyncStorage `cache_shoes_v1` · `cache_runs_v1` | 앱을 즉시 그리기 위한 로컬 사본 |
| 런 사이드카 | AsyncStorage `route_<id>` · `splits_<id>` · `paceTrack_<id>` · `hrTrack_<id>` · `gapTrack_<id>` · `track_<id>` | 상세 화면용 시계열. 레코드와 **분리** 저장 |
| 설정·상태 | AsyncStorage (`challenges_v1` · `medals_v1` · `tombstones_v1` · `hk_linked_v1` · `hr_backfill_pending_v1` 등) | 기능별 로컬 상태 |
| 클라우드 정본 | Firestore `userBackups/{uid}` | 신발·런·설정·진척·메달 (`BackupPayload`) |
| 클라우드 사이드카 | Firestore `userBackups/{uid}/runDetails/{runId}` | 스플릿·페이스·심박·경사 시계열 |
| 사진 | 기기 파일 시스템 (경로만 레코드에 저장) | **백업되지 않는다** — 재설치 시 소실 |

버전 표시는 두 종류다.

- **키 접미사** `_v1` — 그 키의 값 구조가 바뀌면 `_v2` 로 **새 키를 만든다**(구 키는 읽기 전용 폴백으로 남긴다). 예: `hr_recover_sweep_at_v2`.
- **페이로드 버전** `lib/backup.ts` 의 `BACKUP_VERSION`(현재 1) / `SUPPORTED_VERSIONS`(`[1]`). 백업 파일·클라우드 문서의 구조 버전이다.

## 2. 변경 유형별 절차

### ✅ 안전 — 선택 필드 추가
새 필드는 **옵셔널**로 넣고 읽는 쪽에 기본값을 둔다. 구버전이 만든 데이터에는 그 필드가 없다.

```ts
const maxKm = Math.max(0, Number(shoe.max_km) || 0) || DEFAULT_ROTATION_MAX_KM;
```

### ⚠️ 주의 — 기존 필드의 **의미** 변경
같은 이름에 다른 뜻을 담는 것이 가장 위험하다(타입이 같으면 tsc·테스트가 못 잡는다).
의미를 바꿔야 하면 **새 필드를 만들고 구 필드는 유지**한다.

> 실제 사고: 2026-07-26 일괄 편집이 `CARD_HI as SURFACE` 를 `CARD_HI as WARN` 으로 바꿨는데
> 문자열 타입이 같아 tsc·2,052개 테스트가 전부 통과했다. 타입은 의미를 지켜주지 않는다.

### ⚠️ 주의 — 키 이름 변경
새 키로 쓰되, 읽기는 **신 키 → 구 키** 순으로 폴백하고 구 키는 최소 두 번의 릴리스 동안 남긴다.
사용자는 업데이트를 건너뛴다 — 구버전 앱이 신버전 데이터를 만나도 깨지지 않아야 한다(**롤백 안전성**).

### 🚫 금지 — 필드·키 삭제, 파괴적 일괄 변환
지우지 않는다. 안 쓰면 안 읽으면 된다. 저장소를 훑어 값을 덮어쓰는 마이그레이션은
실패 지점(중간에 앱이 죽음)이 곧 데이터 손실이다.

### 페이로드 버전을 올려야 할 때
`BackupPayload` 의 구조 자체가 달라질 때만. 절차:
1. `BACKUP_VERSION` 을 올린다.
2. `SUPPORTED_VERSIONS` 에 **구 버전을 남긴 채** 새 버전을 추가한다.
3. `parseBackup` 에 구 버전 → 신 구조 변환을 넣는다(읽기 시 변환, 저장은 항상 최신).
4. 구 버전 파일을 읽는 테스트를 추가한다.

## 3. 유입 경로가 여러 개라는 사실

런 레코드는 **네 경로**로 들어온다. 저장 구조를 바꿀 때 네 개를 모두 확인한다.

1. 폰 러닝 저장(`RunEngine.onSave`)
2. 워치 런 인제스트(`onWatchRun`)
3. 클라우드 pull(`cloudSync`)
4. 크래시 복구(스냅샷 재개)

> 미해결 과제(F-08): 부팅 캐시의 런 레코드가 GPS 경로를 통째로 안고 있고 같은 경로가
> 사이드키에도 있다. 캐시에서 경로를 빼려면 **네 경로가 모두 사이드키를 쓰도록 먼저 정리**해야
> 한다 — 워치 인제스트·클라우드 pull 이 사이드키를 만들지 않아 오프라인 지도가 사라진다.
> (`App.tsx` `persistRunToCache` 위 주석 참조.)
