| 단계 0 관찰 | 3일 | 심사 통과 후 |

> **결론:** 손으로 하는 일은 **10일(iOS) / 14일(Android 동시)** 이면 끝난다. 출시일은 **방통위 접수일 + 3~6주** 근처에서 정해지고, 그 안에 이 날수는 통째로 들어간다. **그래서 순서 1번이 신고 접수다 — 중요해서가 아니라 남이 처리하는 시간이 제일 길어서다.**

**시간 산정에서 정직하게 밝힐 것**

- B-6 의 6시간 중 **5시간 러닝은 실제로 달릴 필요가 없다.** 앱을 켠 채 5시간 두면(걷기·자전거·가방) 경로점 1.8만 개 규모와 스냅샷 쓰기 지연은 그대로 재현된다. 손이 묶이는 시간은 30분 남짓이다.
- 잠금 30분·백그라운드 복귀·비행기모드·강제종료 재개는 **한 번의 러닝에 묶어서** 할 수 있다. 6시간은 그렇게 묶었을 때의 값이다(v1 은 8시간이었고, 08-05 실측이 거리·백그라운드를 이미 덮어 줄었다).
- **A-2(Health Connect 선언)의 소요는 추정하지 않았다.** 저장소로 판정할 수 없고, 콘솔을 열어봐야 안다. Android 동시 일정의 가장 큰 미지수는 이것이다.
- 실기기 QA 에서 버그가 **하나도 안 나올 확률은 낮다.** 08-05 실측 1회가 버그 4건을 냈다. 그래서 +2일을 미리 잡았다.

| 🔴 **프로필 「1km 최고 00:02」** | 5K 가 31:28(6'17"/km)인 사용자에게 1km 최고가 **2초**로 떠 있었다. 거리는 정상인데 시간이 몇 초인 레코드 하나가 최고 기록 자리를 차지한 것. **3,207 테스트가 전부 그린인 상태**였고 크래시도 아니라 어떤 자동 수단에도 안 잡힌다 | `84b097d` — `MIN_PLAUSIBLE_SEC_PER_KM=100` 불변식을 **두 구현 모두**에 적용(goals·records). 런은 버리지 않고 순위 경쟁에서만 뺀다. 회귀 가드 6건 |
| 🟡 **홈 캐러셀 점이 늦게 따라온다**(민우님 지적) | 점이 `onMomentumScrollEnd` 에서만 갱신 — 관성이 완전히 멎은 뒤에야 바뀐다 | `f4c430f` — 앱 상태와 점을 분리해 점만 손가락을 따라가게. 회귀 가드 3건(특히 *"스크롤 중 onSelect 를 부르지 않는다"* — 부르면 `scrollTo` 가 손가락과 싸운다) |

## C.2 지적하지 않은 것 — 확인해서 걸렀다

**탭바가 콘텐츠를 가리는 것처럼 보였다**(4탭 중 3탭에서). 스크롤 최하단을 다시 찍어 보니
마지막 카드가 탭바 위에 여유를 두고 정상적으로 끝났다 — **mid-scroll 화면만 보고 지적할 뻔했다.**
이 저장소가 기록해 온 감사 오판(06-ux ④ 등)과 같은 패턴이라 남긴다.

## C.3 실측치

| 항목 | 값 | 판정 |
|---|---|---|
| **콜드스타트(첫 프레임)** | **268~422ms** (`am start -W`, 3회) | 좋다 |
| **콜드스타트(내용이 보이기까지)** | **약 3초** — 2초 시점엔 아직 스켈레톤 | 프리미엄 기준(1.5~2s)보다 느리다. 다만 스켈레톤이 *"기록을 불러오는 중이에요"* 로 정직하게 덮는다 |
| 메모리(부팅 직후) | PSS 152MB | RN 앱 통상 범위 |
| **APK 파일** | 184.3MB | ⚠️ **유니버설(ABI 4개) — 착시다** |
| **실사용자 다운로드(arm64)** | **약 81.5MB** | 러닝 앱으로 무난 |
| 그중 **OCR/바코드** | **약 20MB (25%)** | ⚠️ 아래 |

**크기에서 나온 진짜 항목:** 기록증 OCR 하나가 다운로드의 4분의 1을 먹는다 —
`libmlkit_google_ocr_pipeline.so` 11.1MB + **`libbarhopper_v3.so` 4.95MB(바코드 스캐너 —
코드에서 `barcode` 사용 0건)** + 바코드 모델 0.7MB + **안 쓰는 언어 모델**(일본어·데바나가리·
벵골어 등) 약 2MB. **최소 7.6MB 는 아예 안 쓰는 기능이다.**
정공법은 ML Kit 를 번들형 → 온디맨드형(Play Services)으로 바꾸는 것이고,
**네이티브 의존 변경이라 승인 대상**이며 오프라인 첫 OCR 을 잃는다 → §5(출시 후) 항목.

## C.4 못 한 것

- **오염된 런을 특정하지 못했다.** `userBackups` 를 직접 조회하려 했으나 자동 승인 정책에 막혔고
  우회하지 않았다. C.1 의 불변식은 원인과 무관하게 성립하지만, **어느 런인지는 여전히 미확인**이다.
  기록 탭에 0km·0.01·0.05·0.23·0.4km 짜리 테스트 런이 여럿 남아 있으니 **출시 전 정리를 권한다**.
- **디자인 판정은 여전히 부분적이다.** 4탭 + 부팅만 봤고 러닝 중 화면·온보딩·공유 카드는 못 봤다.
