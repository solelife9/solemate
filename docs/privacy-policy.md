# Keego 개인정보 처리방침 — 정본 위치 안내

> **이 파일은 본문을 담지 않는다.** 정본은 아래 두 파일이다.
>
> - 개인정보 처리방침 — [`docs/privacy.html`](./privacy.html)
> - 이용약관 + **위치기반서비스 이용약관** — [`docs/terms.html`](./terms.html)

## 왜 본문을 여기 두지 않는가

2026-07-26 출시 심사에서 **처리방침이 코드와 어긋난 채 방치된 사고(B-02)** 가 확인됐다.

- 방침은 "심박 등 건강 데이터는 기기와 앱 내에서만 처리"라고 적고 있었으나, 실제로는
  `lib/runDetailSync.ts` 의 `hrTrack_` 이 Firestore 로 업로드되고 있었다.
- 방침의 위탁처는 Nominatim 이었으나, 2026-07-17 에 OS 내장 역지오코딩으로 교체됐다
  (`lib/geocode.ts`).

원인은 **같은 문서가 `.md` 와 `.html` 두 벌로 존재**해 한쪽만 갱신됐기 때문이다.
그래서 본문 원본을 `.html` 하나로 합치고, 이 파일은 포인터만 남긴다.

## 갱신 절차

1. `docs/privacy.html` 또는 `docs/terms.html` 을 수정한다.
2. **공개 저장소 `solelife9/keego-legal` 에 같은 파일을 푸시한다**(GitHub Pages 호스팅).
   앱과 스토어가 참조하는 공개 URL 은 `lib/legalLinks.ts` 에 있다.
3. 시행일(문서 상단 `시행일:`)을 갱신한다. 이용자에게 불리한 변경은 시행 30일 전 공지.

## 코드와 문서가 어긋나지 않게 하려면

개인정보 관련 **동작을 바꾸는 변경**(새 항목 수집, 새 위탁처, 클라우드 저장 범위 변경,
보유 기간 변경)은 문서 갱신을 같은 커밋에 포함한다. 특히 다음을 건드릴 때 확인한다.

| 코드 | 문서에서 확인할 곳 |
|---|---|
| `lib/backup.ts` `BackupPayload` | 처리방침 §2 표의 '클라우드 저장' 열 |
| `lib/runDetailSync.ts` `SIDECARS` | 처리방침 §2 건강정보 행 + 건강정보 고지 |
| `lib/firebaseCloudPort.ts` 경로 | 처리방침 §5 위탁 · §6 국외 이전 |
| 새 네이티브 권한(Info.plist / AndroidManifest) | 처리방침 §10 접근 권한 안내 |
| 위치정보 처리 방식 변경 | 이용약관 제2부(위치기반서비스) 제3~5조 |

## 남은 사용자 액션 (코드로 해결 불가)

- **위치기반서비스사업 신고** — 방송통신위원회. 개인위치정보를 처리하므로 필수이며 처리에
  수 주가 걸린다. 출시일을 좌우하는 항목이라 가장 먼저 착수해야 한다.
- **법률 검토** — 위 문서는 표준 양식 기준으로 작성했으나 최종 확인은 전문가 검토 권장.
- **Firestore 리전 확정** — 처리방침 §6 은 "미국 등 Google Cloud 데이터센터 소재 국가"로
  적었다. 콘솔에서 실제 리전을 확인해 더 구체적으로 적을 수 있다.
